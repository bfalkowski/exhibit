    How to label an escaped defect

    Why

    Each label is the base of policy rules. exhibit policy suggest drafts a rule for a category only when two or more labeled defects share it, from two or more PRs. So the same kind of bug needs the same category name.

    What you decide

    Which earlier PR brought this bug, what went wrong in a few words, its category, and the evidence that would have caught it.

    What a link is

    SZZ guessed the PR that brought the bug: it ran git blame on the lines the fix changed. Keep a link when that PR really brought the bug. Reject it when SZZ guessed wrong, for example when the PR only moved or reformatted the line. You can reject every link. The bug is then still real, with no known introducing PR.

    What a category is for

    It groups bugs of the same kind, such as "Race condition". Pick one from the list when it fits. Make a new one only for a new kind of bug.

    When to skip

    Not a bug / skip (3): the fix PR changed behavior on purpose, or is not a bug fix at all. Nothing is written, and the next run of exhibit label shows it again.

    A review finding that was left for a later ticket is a real bug, so label it, and set Known at review to yes. That makes it a deferral, which never counts as a policy miss.

    Later (D): you are not sure yet. Nothing is written, and you can come back to it.

    Keys

    1 Accept, 2 Edit, 3 Not a bug / skip, D Later, ← → Back and Next, K keep every link, R reject every link, ? this help. In a text field, Ctrl+Enter accepts and Esc leaves the field.
